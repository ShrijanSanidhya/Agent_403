## Problem Statement
**Problem 03: Python Vulnerability Reachability Analyzer**

Security scanners flag every vulnerable dependency, even when the vulnerable
function is never used. We are building a tool that checks whether a known
vulnerable function in a Python dependency can actually be reached from a
project's own code.

Each finding is marked as:
- **Reachable**: with the call path as proof
- **Not affected**: with an OpenVEX statement
- **Uncertain**: for dynamic code (e.g. `getattr`, `importlib`) where we cannot be sure

## AI Models Used (in the product)
**qwen2.5-coder:7b**, run locally via Ollama. It reads the advisory text and
the fix diff and picks the public entry points that trigger the vulnerability,
and the safe alternatives. Every name is validated against the package's AST
index. Invented names are rejected.

The same client also supports any open-weight model on an OpenAI-compatible
server (for example the event model server) via `AGENT403_LLM_BASE_URL`.
Without a model, a static fallback is used. That fallback is low confidence.

The shipped symbols cache covers 122 advisories across 15 packages, generated by qwen2.5-coder:7b during the hackathon; only the PyYAML and Jinja2 key entries were manually reviewed.

## Why this model
- **Open-weight and local**: no API keys.
- **Built for code**: good at reading diffs.
- **Laptop-friendly size**: 7B runs on a laptop.

The call-graph analysis is deterministic Python (`ast` module), so the
model is used only where it adds real value.
